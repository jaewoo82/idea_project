# PDF/캡쳐 이미지 회로도 자동 Draw (CircuitJS1 연동)

## 사용자 관점 결과

- 사용자가 PDF 파일(전체 또는 일부 회로도)을 업로드하면, 화면에 임베드된 CircuitJS1 시뮬레이터에 회로가 자동으로 그려진다.
- 사용자가 회로도를 캡쳐(예: Windows 캡쳐 도구)해서 클립보드에 담긴 상태에서 페이지에 Ctrl+V로 붙여넣으면, PDF 업로드와 동일하게 인식 → (애매한 지점이 있으면 확인 팝업) → 자동 Draw가 실행된다.
- 시스템이 소자 종류나 연결 관계를 확신하지 못하는 지점마다, 사용자는 "후보 목록 + 그 외(직접 입력)" 형태의 팝업에서 하나를 선택해 확정한다.
- 모든 애매한 항목이 해결되면 최종 회로가 그려지고, 사용자는 CircuitJS 자체의 전압/전류 시뮬레이션 기능을 바로 사용할 수 있다.
- 업로드 시 "일부 회로"로 표시한 경우, 사용자는 "이 회로는 일부만 그려졌다"는 사실을 화면에서 명확히 확인한다. 시스템이 열린 배선 끝 등을 발견하면 추가로 경고를 보여준다.
- 사용자는 CircuitJS 자체 저장/내보내기 기능(텍스트/URL/로컬 파일)으로 결과를 저장할 수 있다.

## 승인된 범위

- PDF 업로드 UI, 업로드 시 "전체 회로 / 일부 회로" 명시적 선택.
- PDF에서 소자 기호, 값 텍스트(OCR), 배선 연결관계를 규칙 기반으로 인식하는 파이프라인. 인식 로직은 교체 가능한 인터페이스 뒤에 둔다.
- 인식 결과를 CircuitJS의 회로 텍스트 포맷(각 줄 `타입 x1 y1 x2 y2 flags 값...`)으로 변환.
- 변환된 텍스트를 iframe으로 임베드된 CircuitJS1에 주입해 회로를 자동으로 그리는 기능.
- MVP 소자 범위: 저항, 커패시터, 인덕터, 전압원, 접지, 배선, 다이오드, 트랜지스터.
- 소자 종류 또는 연결 대상이 애매할 때, 후보+커스텀 입력 팝업으로 사용자에게 확정받는 상호작용.
- 시스템이 감지한 "열린 배선 끝" 등 부분 회로 단서에 대한 보조 경고 표시.
- CircuitJS1을 iframe으로 임베드해서 프로젝트에 편입(공식 호스팅 페이지를 iframe src로 사용; 로컬 빌드 환경이 갖춰지면 정적 자산 self-host로 교체 가능).
- 클립보드 붙여넣기(Ctrl+V) UI. PNG/JPEG 등 래스터 이미지 입력을 받아 회로 인식을 실행한다.
- 래스터 이미지 전용 인식 경로. 텍스트는 실제 OCR로 읽고, 도형은 연결된 잉크 영역(연결요소) 단위로 분리해 기본 형태 규칙으로 1차 분류를 시도하되, 확신이 낮으면 적극적으로 애매함 확인 팝업으로 넘긴다.
- PDF 경로와 이미지 경로 모두 같은 인식 엔진 인터페이스, DSL 생성, 애매함 확인, 미지원 표시, 부분 업로드 배너, 열린 배선 끝 경고를 공유한다.

## 관찰 가능한 수용 기준

1. 정형 스키매틱 PDF(전체 회로, 지원 소자 범위 내)를 업로드하고 "전체 회로"를 선택했을 때 애매함이 전혀 없으면, 별도 팝업 없이 CircuitJS 화면에 회로가 자동으로 그려지고 시뮬레이션이 즉시 동작한다(소자를 클릭하면 전압/전류 값이 표시된다).
2. 인식 과정에서 소자 종류나 연결 대상이 애매한 지점이 있으면, 사용자는 각 항목마다 "후보 N개 + 그 외(직접 입력)" 팝업을 보고, 선택을 마친 뒤에야 해당 지점이 회로에 반영된다.
3. 사용자가 "그 외(직접 입력)"를 선택해 값을 직접 입력하면, 그 입력값이 최종 회로에 반영된다.
4. 사용자가 업로드 시 "일부 회로"를 선택하면, Draw 후 화면에 "이 회로는 일부만 표시되었다"는 안내가 명확히 보인다.
5. 시스템이 열린 배선 끝(다른 소자에 연결되지 않은 배선 끝)을 감지하면, "전체 회로"를 선택했더라도 해당 지점에 보조 경고가 표시된다.
6. MVP 소자 범위 밖의 소자가 PDF에 있으면, 그 소자는 회로에 배치되지 않고 "식별했지만 미지원"으로 목록에 표시된다.
7. 사용자가 애매한 항목에 "모르겠음"으로 남기고 진행하면, 해당 위치는 실제 회로 소자가 아니라 명확히 구분되는 placeholder 라벨로 표시되고 시뮬레이션 동작을 방해하지 않는다.
8. 사용자는 CircuitJS 화면의 자체 저장/내보내기 메뉴(텍스트/URL/로컬 파일)로 결과를 저장할 수 있다. 앱은 별도의 저장 화면이나 저장소를 제공하지 않는다.
9. 클립보드에 이미지가 담긴 상태에서 페이지에 Ctrl+V로 붙여넣으면, PDF 업로드와 동일한 인식 → (애매함 있으면 팝업) → 자동 Draw 흐름이 실행된다.
10. 이미지 경로에서 인식 확신이 낮은 소자는 적극적으로 "애매함" 팝업으로 사용자 확인을 거친다. PDF 경로였다면 확신 있게 분류됐을 정도의 형태라도, 래스터 인식에서는 더 쉽게 애매함으로 분류될 수 있다.
11. 이미지 경로로 회로 요소를 전혀 찾지 못하거나 클립보드에 이미지가 아닌 데이터가 있으면, 사용자에게 명확한 오류 메시지를 보여주고 PDF 업로드 흐름은 그대로 사용할 수 있다.

## 정해진 제약과 근거

- CircuitJS1은 npm 임포트가 아니라 iframe 임베드로 편입한다. Java/GWT 산출물이라 다른 임포트 방법이 없다는 것을 소스 조사로 확인했다. 이 개발 환경에는 Java/GWT 빌드 도구가 없고 사전 빌드된 배포본도 없어, 직접 컴파일한 정적 자산을 self-host하는 대신 공식 호스팅 페이지(falstad.com/circuit)를 iframe src로 가리킨다. 빌드 환경이 갖춰지면 정적 자산 self-host로 교체할 수 있다 (`AGENTS.md`의 "벤더 기술: CircuitJS1" 블록 참고).
- 자동 Draw는 UI 클릭 시뮬레이션이 아니라 CircuitJS의 텍스트 DSL(각 줄 `타입 x1 y1 x2 y2 flags ...`)을 생성해 주입하는 방식으로 구현한다. CircuitJS가 공식적으로 지원하는, 마우스 좌표 재현보다 훨씬 안정적인 경로다.
- 인식 엔진은 규칙 기반(OCR + 이미지 처리)으로 시작하고 교체 가능한 인터페이스 뒤에 둔다. 현재 환경에서 외부 AI/vision API를 쓸 수 없기 때문이며, 근거와 재검토 조건은 [ai-assisted-recognition](../../decisions/ai-assisted-recognition.md)에 있다.
- MVP 지원 소자는 저항/커패시터/인덕터/전압원/접지/배선/다이오드/트랜지스터로 한정한다.
- 부분 업로드 여부는 사용자가 업로드 시 명시적으로 선택하고, 시스템은 열린 배선 끝 등을 근거로 보조 경고만 덧붙인다. 연결관계 추론만으로 전체/부분을 완전 자동 판별하는 것은 신뢰도가 낮다고 사전 조사에서 확인했다.
- 결과 저장은 CircuitJS 자체 기능(텍스트/URL/로컬 파일 내보내기)만 노출한다. 별도 저장소를 만들지 않아 이번 스펙의 범위를 "PDF → 자동 Draw"에 집중시킨다.
- 클립보드 이미지 인식은 기존 pdfjs-dist 기반 벡터 파이프라인을 재사용하지 않는다. 래스터 이미지에는 벡터 경로나 PDF 텍스트 레이어가 전혀 없다는 것을 소스 조사로 확인했다. 별도의 래스터 인식 경로를 새로 구현하되, 기존과 같은 인식 엔진 인터페이스를 구현해 하위 흐름(애매함 팝업, DSL 생성, iframe 주입, 부분 업로드 배너, 열린 배선 끝 경고)을 그대로 공유한다.
- 래스터 경로는 확신 있는 분류보다 애매함 확인을 우선한다. 텍스트는 실제 OCR로 읽고, 도형은 연결요소 단위로 나눈 뒤 기본 형태 규칙으로 1차 분류를 시도하되, 확신이 낮으면 조용히 추측하지 않고 적극적으로 사용자 확인 팝업으로 넘긴다([ai-assisted-recognition](../../decisions/ai-assisted-recognition.md)의 기존 원칙을 래스터 경로에도 그대로 적용).
- 붙여넣기는 페이지 어디서든 Ctrl+V(전역 paste 이벤트)로 동작하고, 한 번에 이미지 한 장을 처리한다.

## 가정

- MVP는 페이지 수와 무관하게 각 페이지를 독립된 회로로 처리한다. 여러 페이지가 이어지는 회로라도 페이지 간 자동 병합은 지원하지 않으며, 필요하면 사용자가 페이지별로 나눠 업로드한다. 페이지 간 연결 추론은 단일 페이지 내 추론보다 훨씬 불확실해서, 실제로 필요하다는 근거가 쌓이면 별도로 다룬다.
- 모든 애매 항목에 대한 사용자 응답을 받아야 최종 Draw를 실행한다. 사용자가 특정 항목을 "모르겠음"으로 남기면 해당 지점은 placeholder로만 표시되고 실제 회로 소자로 배치되지 않는다.
- 인식 파이프라인(OCR, 도형 인식)이 사용할 구체적 라이브러리는 이번 스펙에서 정하지 않는다. 구현 단계의 판단으로 남긴다.
- "애매함"을 판정하는 구체적 신뢰도 임계치는 이번 스펙에서 수치로 고정하지 않는다. "애매하면 반드시 사용자에게 확인받는다"는 동작만 요구하고, 임계치 자체는 구현 중 조정 가능한 값으로 남긴다.
- 클립보드 이미지 형식은 PNG/JPEG 등 브라우저가 붙여넣기로 표준 제공하는 이미지 MIME 타입을 가정한다. 한 번에 여러 이미지를 붙여넣는 경우는 다루지 않는다.
- 래스터 인식 파이프라인이 사용할 구체적 이미지 처리·OCR 라이브러리는 이번 스펙에서 정하지 않는다. 구현 단계의 판단으로 남긴다(PDF 경로와 같은 원칙).

## 범위 밖과 이유

- 손으로 그린(freehand) 회로도 인식 — 입력 PDF는 정형 스키매틱 중심이라고 확인되어 스코프에서 제외한다. 手그림 입력이 실제로 필요해지면 재검토한다.
- 외부 AI/vision API 연동 구현 — 현재 환경에서 API 접근이 불가능해 구현하지 않는다. 인터페이스만 교체 가능하게 열어둔다 ([ai-assisted-recognition](../../decisions/ai-assisted-recognition.md) 참고).
- 앱 자체의 회로 저장소(DB, 재열람 화면) — CircuitJS 자체 저장/내보내기 기능만 노출하고 별도 저장소는 만들지 않는다.
- CircuitJS가 지원하는 소자 전체(논리 게이트, 연산증폭기, 커스텀 IC 등) — MVP 소자 범위 밖의 소자는 "식별했지만 미지원"으로만 표시하고 배치는 보류한다.
- 여러 페이지로 이루어진 PDF에서 페이지 간 연결을 자동으로 병합하는 것 — 위 가정 참고.
- 손으로 그린 회로도를 사진으로 찍거나 스캔한 이미지 인식 — 클립보드 캡쳐 이미지도 컴퓨터로 그려진 회로도(EasyEDA/KiCad/PDF 뷰어 등)를 캡쳐한 것을 전제로 하며, 손그림 사진/스캔은 여전히 범위 밖이다.
- 여러 장의 캡쳐 이미지를 하나의 회로로 이어붙이는 것 — 여러 페이지 PDF를 자동 병합하지 않는 것과 같은 이유다.
- 캡쳐 이미지의 회전 보정, 원근 보정, 노이즈 제거 같은 전처리 — 있는 그대로의 캡쳐 이미지를 인식 대상으로 삼는다.

## 보류된 결정

- 외부 AI/vision API를 이용한 인식 엔진 구현 — 환경에서 API 접근이 가능해지는 시점에 재검토한다. 그때까지는 규칙 기반 구현이 이 기능의 유일한 구현체다.
- 애매함 판정 임계치의 구체적 수치와 튜닝 — 구현 중 실제 인식 정확도를 보고 결정한다.
- 여러 페이지 PDF의 페이지 간 자동 연결 병합 — 필요성이 실제로 확인되면 별도 스펙으로 다룬다.
- 래스터 경로의 실제 인식 정확도와, 그에 따라 형태 규칙을 더 정교화할지 여부 — 실제 캡쳐 이미지로 검증한 뒤 재검토한다.

## 남은 위험

- 규칙 기반 인식의 정확도가 낮으면 거의 모든 소자가 확인 팝업으로 이어져, 사용자가 반복적으로 확인해야 하는 피로도가 커질 수 있다.
- PDF마다 스키매틱 표기 관례(저항 기호가 지그재그인지 사각형인지, 미국식/유럽식 표기 등)가 달라 규칙 기반 인식기가 처리해야 할 변형이 예상보다 많을 수 있다.
- PDF 좌표를 CircuitJS 그리드 좌표로 변환하는 과정에서, 소자 간 상대적 배치는 맞아도 겹침이나 간격 문제로 그려진 회로가 시각적으로 어색해질 수 있다.
- CircuitJS1을 self-host하지 않고 공식 호스팅 페이지를 iframe으로 직접 가리키기 때문에, 그 사이트가 다운되거나 URL/쿼리 파라미터 동작이 바뀌면 이 기능 전체가 영향을 받는다.
- 래스터 인식은 PDF 벡터 인식보다 훨씬 많은 항목을 "애매함"으로 분류할 가능성이 높아, 이미지 경로 사용자는 팝업을 더 자주 마주칠 수 있다. 의도된 정책이지만 실사용성에 영향을 줄 수 있다.
- 캡쳐 이미지의 해상도·압축·기울어짐에 따라 인식 자체가 거의 되지 않을 수 있다(대부분의 요소가 애매함 또는 미지원으로 빠질 위험).
