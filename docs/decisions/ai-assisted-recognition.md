# AI 기반 인식 기능 설계 원칙

## Decisions

- 이 프로젝트 환경에서는 외부 AI/vision API(예: 이미지를 입력받는 Claude API 호출)를 사용할 수 없다. AI의 인식·분류·추론 능력이 필요한 기능은 우선 규칙 기반(OCR + 이미지 처리 규칙)으로 구현한다.
- 인식·분류처럼 결과가 애매할 수 있는 로직은 교체 가능한 인터페이스 뒤에 둔다. 지금의 규칙 기반 구현과 향후 API 기반 구현이 같은 인터페이스를 통해 서로 교체될 수 있어야 한다.
- 인식 결과가 애매한 경우 시스템은 조용히 추측하지 않는다. 사용자에게 후보 목록과 "그 외(직접 입력)"를 함께 제시하는 상호작용으로 확정한다.

## Boundaries

- 이 원칙은 확률적으로 애매한 결과가 나올 수 있는 인식/분류 기능에 적용된다. 결정적으로 계산 가능한 로직에는 적용하지 않는다.
- "교체 가능한 인터페이스"는 지금 두 번째(API 기반) 구현체까지 함께 만들라는 뜻이 아니다. 실제로 API 접근이 가능해졌을 때 구현하면 된다.

## Why

현재 실행 환경이 외부 API 호출을 지원하지 않지만 이 제약은 영구적이지 않다. 인식 로직을 인터페이스 뒤에 분리해두면 나중에 API 접근이 가능해졌을 때 규칙 기반 구현을 교체하는 것만으로 정확도를 높일 수 있다. 또한 규칙 기반 인식은 정확도가 완벽할 수 없으므로, 애매한 결과를 사용자가 직접 확정하게 하는 편이 잘못된 결과를 조용히 반영하는 것보다 안전하다.

## Reconsider when

- 프로젝트 환경에서 외부 AI API 호출이 가능해져서 인터페이스의 두 번째 구현체를 실제로 추가하게 될 때
- 사용자가 애매한 항목마다 선택해야 하는 상호작용이 반복 사용을 방해할 정도로 빈번하다는 근거가 쌓일 때

## Still-rejected alternatives

- 외부 API 없이 완전 자동 판정만 시도하고 애매한 부분을 최선의 추측으로 조용히 채우는 방식 — 인식 오류가 사용자 눈에 띄지 않은 채 결과에 그대로 반영될 위험이 크다.
